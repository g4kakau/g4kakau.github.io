{% comment %} Overrides `_includes/analytics/goatcounter.html` from jekyll-theme-chirpy. The theme's version loads count.js with no settings, which sends the FULL query string twice: once inside `p` (`get_path()` returns `pathname + search`) and again as its own `q` parameter, which count.js sets unconditionally from `location.search`. That is how `fbclid` reached zgo.at. Every post link shared on Facebook comes back with one attached, and Kakau's own campaign links carry `utm_*`. None of it is needed to count a page. Kakau keeps GoatCounter: it is the only consumer of the five `notes_to_*` CTA events (`kakau-analytics.html`) and it backs the per-post view counter. What it does not need is the query string. See `docs/analytics.md` and the Academy's `docs/PRIVACY_GAP_REVIEW_stage5.md`. Three changes, and each is load-bearing: 1. `path` returns `location.pathname` instead of the default `pathname + search`. 2. `q` is blanked by wrapping `get_data` AFTER count.js defines it -- there is no setting for this one. `urlencode()` skips empty values, so a blank `q` is omitted from the request entirely rather than sent as `q=`. 3. `referrer` is reduced to its origin. Enough to tell Facebook from Google; not enough to carry the other site's own query string. Same-origin referrers become empty, since an internal click is not a referral. `no_onload` is what makes (2) possible. count.js counts the page view as soon as it executes, and the script is `async`, so an onload handler would fire too late to patch anything. With `no_onload` the count is ours to make, after the patch is in place. The five events are unaffected: `get_data` prefers an explicit `vars.path` over the `path` setting, so `count({path: 'event/notes_to_apply'})` still sends exactly that.
