# Publishing pipeline — current architecture

How a post gets from a file in `_posts/` to a live page on
`notes.kakau.tw`, and what gates it along the way. This describes the
system as implemented — if this doc and the actual code disagree, the code
is right and this doc needs fixing.

For the one-time delivery notes this architecture originally shipped under,
see [`docs/history/2026-09-06-two-site-integration-delivery.md`](../history/2026-09-06-two-site-integration-delivery.md)
(historical, not current — this file is the current description).

## 1. Front matter → Jekyll defaults

`_config.yml`'s `defaults` block applies to every file under `_posts/`
without needing to repeat it per post: `layout: post`, `comments: true`,
`toc: true`, `author: sin-iu-ho` (see `_data/authors.yml`), and the fixed
permalink `/posts/:title/`. Changing that permalink pattern requires
updating every other post link in the project — it's flagged as
do-not-touch in `_config.yml` itself.

Category/tag archive pages (`/categories/:name/`, `/tags/:name/`) are
generated by the `jekyll-archives` plugin from each post's front matter —
see [`docs/content/taxonomy.md`](../content/taxonomy.md) for the rules
governing `categories` values.

## 2. Build-time content injection

`_plugins/kakau_integration.rb` registers a `Jekyll::Hooks` `:posts,
:pre_render` hook that appends two includes to **every** post's rendered
content automatically:

```
{% include contextual-cta.html %}
{% include ecosystem-footer.html %}
```

This is why authors never hand-write CTA markup in a post — the hook adds
it uniformly, so there's exactly one code path that can get it wrong,
instead of 90+.

- **`contextual-cta.html`** looks up `site.data.kakau.contextual_ctas[page.slug]`
  (defined in `_data/kakau.yml`). If the current post isn't in that mapping,
  it renders nothing. If it is, it shows a CTA pointing at either `sample`
  or `syllabus` (from `_data/kakau.yml`'s `academy` URLs, each already
  carrying `utm_source=kakau_notes&utm_medium=referral&utm_campaign=content_flywheel`),
  appends `&utm_content=article_cta`, and fires a GoatCounter event
  (`notes_to_sample` or `notes_to_syllabus`).
- **`ecosystem-footer.html`** always renders, linking to the academy home,
  sample, and syllabus with `&utm_content=article_footer` and their own
  GoatCounter events.

Site-wide (not per-post) integration points:

- `_includes/sidebar.html` — a minimal Chirpy override adding one physics-academy
  entry to the global sidebar, not a copy of the whole layout.
- `_tabs/academy.md` — the `/academy/` bridge page: explains the relationship
  between the free public notes and the paid academy, deliberately holds no
  pricing/schedule/enrollment-condition facts (those live only on `kakau.tw`,
  the single source for that information).
- `/paths/` — an editorial learning-path layer that curates posts into a
  reading order, coexisting with (not replacing) the `categories` taxonomy.
- `tutoring-plans/index.html` — a `layout: null` redirect stub preserving
  the old pre-migration URL; it captures attribution (see below) before
  `location.replace`-ing to `/academy/`, and is not a primary nav destination.

## 3. Analytics and attribution (site-wide includes)

- `_includes/analytics/goatcounter.html` overrides the Chirpy theme default
  to avoid sending query strings (including `fbclid`) to GoatCounter — see
  [`docs/operations/analytics.md`](../operations/analytics.md) for why and
  what it must keep doing.
- `_includes/kakau-attribution.html` is included from `_includes/footer.html`
  (site-wide, covers ~all pages) and separately from `tutoring-plans/index.html`
  (the one ingress the footer doesn't cover before its redirect) to capture
  first-touch attribution — see [`docs/operations/attribution.md`](../operations/attribution.md).
- Author identity: `_data/authors.yml` holds the canonical `Person` `@id`
  (`https://kakau.tw/about/#person`); `_plugins/author_identity.rb` injects
  that `id` into the `jekyll-seo-tag`-generated JSON-LD author object, so
  the byline a reader sees and the entity a crawler sees can never diverge.
- Comments: Giscus, configured directly in `_config.yml`
  (`comments.giscus.*`) — current repo binding described in
  [`docs/operations/domain-dns.md`](../operations/domain-dns.md).

## 4. CI gate — what has to pass before a page goes live

`.github/workflows/pages.yml` triggers on push to `theme` (and manual
dispatch). Its `build` job runs, **in this order**, and any failure blocks
deploy:

1. `bundle exec jekyll build -d _site` (`JEKYLL_ENV=production`)
2. `node --test tools/test_attribution.mjs` — the cross-subdomain attribution
   contract (12 cases)
3. `node --test tools/test_goatcounter.mjs` — GoatCounter request
   minimization and event names (5 cases)
4. `bash tools/check_integration.sh` — legacy-domain/CTA leak checks, the
   GoatCounter override's presence, terminology (`tools/check_terminology.rb`),
   author/brand identity pins, and the attribution script's contract pins
5. `bundle exec htmlproofer _site --disable-external` — internal link/anchor
   integrity

Only after all five pass does `deploy-pages@v4` publish to GitHub Pages.

## 5. Local equivalent

`tools/test.sh` reproduces the build + `htmlproofer` steps locally (not the
attribution/GoatCounter/terminology checks, which need to be run
separately — see the commands in
[`docs/content/authoring.md`](../content/authoring.md) §6). Run all of them
before committing new or changed posts; passing means the technical layer
isn't broken, not that the content has been audited — see
[`docs/content/audit-policy.md`](../content/audit-policy.md) for what
"audited" means.
