# Kakau 圖表產製系統：設計方案調查

> 狀態：研究／決策草案（非規範）。
>
> 本文處理「已決定需要一張圖後，如何把它可靠地做出來」；不建立選題或
> 文章待辦清單。若決策被採納，再將其中的發布規則整合到
> [`authoring.md`](authoring.md)，使其成為唯一的技術真本。

## 0. 要解決的問題

Kakau 的圖不應只是段落旁的裝飾。它應讓讀者看見一個文字或公式不容易承載的
關係：幾何位置、因果方向、量的比較、隨時間的演變，或可操作的變化。

既有做法已有可用的基礎：站內多數說明圖是 SVG、以 light／dark 成對發布，少數
精確數學圖保留了 TikZ 原始檔。不過目前仍有三個結構性缺口：

1. 直接編寫 SVG 時，產出檔往往也是唯一來源，難以系統性地同時更新雙主題版。
2. 不同圖型沒有明確的選擇規則，因而容易把流程圖、幾何圖、資料圖混用同一種工具。
3. 可讀性、可近用性、科學正確性與原始資料的驗收，尚未是每張圖的交付條件。

AI 影像生成不是上述缺口的解答：它對精確標籤、比例、可重現性與向量輸出均沒有
可靠保證，且 prompt 反覆微調的成本高。因此它不列入教材主圖的正式產線。

## 1. 本次調查的限制與可用條件

| 面向 | 現況／判讀 |
|---|---|
| 發布環境 | Jekyll + Chirpy；既有文章已能以 `mermaid: true` 渲染 Mermaid。 |
| 現有資產 | `assets/img/posts/<slug>/` 存輸出，`src/` 可存可編輯來源；既有規範要求說明圖提供 light／dark SVG。 |
| 本機工具 | 已有 Graphviz `dot`、LuaLaTeX／pdfLaTeX、dvisvgm、rsvg-convert；未安裝 Inkscape、SVGO。 |
| 優先條件 | 繁體中文標示、深淺主題、行動閱讀、長期可修改、可連回證據或資料、能經由 git 檢視。 |
| 不採用的假設 | 不假設每位作者有 Figma、Inkscape 或付費 AI 訂閱；不讓外部 CDN 或執行期 JavaScript 成為靜態教學圖的必要條件。 |

SVG 本身能作為獨立檔案或嵌入 HTML 的圖形文件，並原生提供 `title`、`desc`、`metadata`
等描述結構。[SVG 2 文件結構](https://www.w3.org/TR/SVG2/struct.html) 因此足以作為
靜態教學圖的共同交付格式。

## 2. 方案比較

| 方案 | 最合適的圖 | 優點 | 主要限制 | 建議定位 |
|---|---|---|---|---|
| 直接／程式產生 SVG | 示意、機制、分層、座標、帶標籤的科學圖 | 向量、可版控、精準控制版面與中文標示 | 需要建立共享元件與雙主題生成方式 | **預設正式產線** |
| TikZ → SVG | 幾何、函數、推導、精確數學物件 | 公式、座標和線條具有可重現的語意；既有來源可延續 | 編譯工具與中文字型需固定；不適合自由插畫 | **數學／幾何專用** |
| 資料程式 → SVG | 天文觀測、統計、實驗曲線、時序資料 | 資料與視覺可追溯，重算容易 | 要定義資料來源、單位、版本與圖表語意 | **資料圖專用** |
| Graphviz DOT → SVG | 大型依賴關係、概念網、分類樹 | 自動排版、文字來源可 review；可由 `dot` 輸出 SVG | 學科圖的空間語意和美術控制不足 | **結構圖專用** |
| Mermaid | 簡單流程、內部草圖、低風險摘要 | Markdown 式文字定義、修改快速；支援 SVG 與可近用標題／描述 | 網頁執行期渲染；細節版面、中文密度與學科符號控制有限 | **草稿或簡單流程，不作教材主圖預設** |
| 向量編輯器輸出 SVG | 需要藝術編排的地圖、剖面、複合示意 | 人工調整速度快、構圖自由 | 二進位或冗長 XML 容易難以 review；工具可得性不一致 | **例外通道，來源檔必須隨圖保存** |
| 互動式 SVG／JS | 操作才能理解的參數掃描、投影、幾何變換 | 能讓讀者檢驗「改變什麼、結果如何」 | 開發、測試與無 JavaScript 回退成本高 | **有明確操作學習目標才使用** |
| 生成式 AI 影像 | 情境開場、非測量性的氣氛插圖、構圖探索 | 快速取得視覺方向 | 無法保證科學正確、標籤、比例、向量與版權／來源可追溯性 | **不進教材主圖；如使用，僅作明確標示的輔助插畫或創作參考** |

Mermaid 的官方定位是把文字定義在瀏覽器中動態渲染成圖，目的在降低文件過時的成本；
它也能產生帶 `title`、`desc` 的 SVG。這適合流程的可維護性，不等於適合有精確
空間語意的學科插圖。[Mermaid 官方介紹](https://mermaid.js.org/intro/)、
[可近用性文件](https://mermaid.js.org/config/accessibility.html)。Graphviz 則提供 DOT
語言和 SVG 輸出，適於「關係優先、版面次要」的圖。[Graphviz 文件](https://graphviz.org/documentation/)、
[SVG 輸出](https://graphviz.org/docs/outputs/svg/)。

## 3. 建議：一個格式、五條產線

交付格式統一為**靜態 SVG 優先**，但不要用單一作者工具強迫所有題材。依圖的學習
任務路由：

```text
先問：讀者必須從圖中看見什麼？
  ├─ 精確的幾何／公式關係 → TikZ → SVG
  ├─ 資料的數值、趨勢、不確定度 → 可重跑資料圖 → SVG + 資料表
  ├─ 節點與關係的拓撲 → DOT → SVG
  ├─ 因果、空間、機制或教學標示 → 結構化 SVG（直接或產生器）
  ├─ 必須由讀者拖曳或調參才理解 → 互動 SVG/JS + 靜態回退圖
  └─ 不傳遞可檢驗的知識 → 不必畫；若只是氣氛，再考慮插畫
```

其中第四條是全站主力。它不是「徒手存一張 SVG」：應以簡短、可讀的來源（SVG 模板、
資料檔與小型產生器）產生兩個主題輸出。現有 TikZ 圖已示範相同理念：同一來源經旗標
輸出 light／dark，而不是維護兩幅彼此漂移的圖。

## 4. 每張正式圖的交付契約

一張正式圖至少應具備以下七項；缺任一項，仍視為草稿。

| 交付項 | 要回答的問題 |
|---|---|
| `job` | 讀者看完圖後能判斷、比較或操作什麼？一張圖只承擔一個主要工作。 |
| `claim` | 圖所支持的句子是什麼？文章正文必須把這句話說出來。 |
| `source` | 原始 SVG／TikZ／DOT／腳本、資料與授權來源位於何處？ |
| `render` | light／dark 輸出如何由同一來源重建？使用什麼命令或旗標？ |
| `evidence` | 數值、觀測資料、尺度及「非按比例」聲明的依據是什麼？ |
| `access` | 有意義的 `alt`、圖號與 caption；複雜圖的正文另有趨勢／結論或資料表。 |
| `review` | 已在 320 px 與桌面寬度、light／dark、非彩色辨識和文章脈絡中檢查。 |

複雜圖不能只靠短 alt。W3C 建議以短描述辨識圖像，並提供可被所有讀者使用的長描述；
正文也應直接指出讀者該看見的趨勢或關係。[W3C 複雜圖像指引](https://www.w3.org/WAI/tutorials/images/complex/)。

## 5. 建議的來源與輸出佈局

```text
assets/img/posts/<slug>/
  eclipse-geometry-zh-light.svg       # 發布檔
  eclipse-geometry-zh-dark.svg        # 發布檔
  src/
    eclipse-geometry.svg              # 或 .tex / .dot / 產生器
    eclipse-geometry.data.csv         # 僅資料圖需要
    eclipse-geometry.readme.md        # 重建命令、證據、非按比例聲明
```

不需要為每張小圖新建完整的建置系統；但只要一張圖不是人工一次性手繪，就需要能從
`src/` 重建的最小說明。若同一篇文章有多張相似圖，才提煉共同色票、箭頭、節點、
標籤與輸出指令。

## 6. 視覺語言的最低規格

- **位置有語意。** 天文的視線、軌道投影與相位；物理的力、場、電流；數學的座標與
  對應，都不能為了好看任意移位。非按比例時明講。
- **色彩不是唯一編碼。** 除了色彩，同時用實／虛線、箭頭、填紋、形狀或標籤區分。
- **標籤是內容。** 中文採可取得的 sans 字型 fallback；避免把文字轉 path，除非授權
  或跨平台重現迫使如此做。保留 `<title>`、`<desc>`、`viewBox` 與語意化群組。
- **一套穩定語法。** 從現有圖萃取中性前景、弱背景、主藍色與警示色；顏色的意義要在
  同一篇、同一系列中固定，先不要過早宣布全站色彩分類法。
- **文章優先。** 圖要在正文中被引介、解讀並回收；caption 說明「怎麼讀」，不能只重複
  圖中標籤。

## 7. 不建議的捷徑

1. **以 AI 圖取代可驗證圖。** 它可以是構圖草圖，不能取代幾何、尺度、資料或可讀標籤。
2. **把 screenshot 當教材圖。** 除非截圖本身是研究對象；否則應重畫為向量或附上原始資料。
3. **只交付輸出檔。** 這會使下一次修一個符號或深色版變成重做。
4. **為每張圖加入前端依賴。** 靜態圖不該因網路或 JavaScript 失效；互動圖必須有靜態
   fallback 和可讀說明。
5. **把 Mermaid／Graphviz 當排版工具。** 它們負責描述與自動佈局，不適合承諾教科書級
   的精準視覺構圖。

## 8. 導入順序（不增加內容待辦）

1. 先選各一個「機制 SVG、精確幾何 TikZ、資料 SVG、關係 DOT、互動回退」的代表圖型，
   只驗證產線，不以文章數量作績效。
2. 以這五張結果確定來源檔命名、重建說明、雙主題生成與檢視方法。
3. 再把通過的交付契約與嵌入模板移入 `authoring.md`；此時才是規範生效。
4. 舊文只在自然修訂時補來源或替換明顯不足的圖，不開另一份大規模補圖待辦。

## 9. 本次決策建議

採用「SVG 優先、來源必留、任務分流、靜態預設、可近用驗收」；現階段不安裝新套件、
不採用 AI 生成為科學圖的正式途徑，也不把 Mermaid 升格為教材主圖工具。

下一步的工作不是再蒐集工具清單，而是以一組小型代表圖檢驗這個契約能否真正降低
修改成本並維持教科書品質。
